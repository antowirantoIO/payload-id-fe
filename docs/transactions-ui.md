# Transaction UI preview

Route: `/payments/transactions`. The previous URL redirects here.

The page uses mock data only, visibly labeled. Fixtures follow Payment `dto/response/transaction.go` and the transaction/settlement status enums. Decimal amounts remain strings at the DTO boundary. Tenant/merchant/provider/channel references and optional timestamps are retained. No transaction API or financial mutation is called. Authentication still uses the existing IAM session.

## Reference implementation

The Transaction Workspace uses the copied `components/shared/data-table` components, with intentional fixes for local sorting/pagination and full-width display. It is no longer source-identical to the reference. Default columns separately show platform reference, external/order ID, merchant, transaction type, channel code, transaction status, settlement status, amount, fee, net amount, customer name, environment and creation timestamp (UTC). Each cell represents one field; timestamps display date and time on a single line. Comfortable density and explicit column widths are the default, with horizontal scrolling rather than squeezing columns. Customer email, paid time and expiry time are available in View. Operational tabs narrow the result set; saved views capture the active tab as well as filters and presentation settings. Preview tools and temporary saved views are collapsible.

Multi-search has a draft dialog with Apply/Cancel and duplicate removal. It searches across references and customer fields rather than offering a field-specific selector. Period presets use the current UTC date; fixtures remain anchored to November 14, 2026, so relative presets can return no results. Manual ranges include time and apply only on confirmation. Quick period/status/channel conditions always combine with AND, independently of the advanced group's AND/OR setting. The detail panel supports reference copying with feedback and previous/next navigation through the filtered, sorted results. Opening/closing detail does not replace the table or reset pagination. No Supabase saved-view or invoice mutation code was copied.

Saved views currently live in component memory and disappear after unmount. Setting a default marks the local view only; there is no persisted startup preference. Export produces a client-side mock CSV, not a backend report. Filter-builder AND/OR operations are evaluated locally and are not claims about backend query capabilities. Some shared controls retain their reference English labels. Full cross-locale copy and full pixel-level screenshot parity remain separate verification work.

## Verification

Bulk selection offers callback and provider-resync mock previews with confirmation, a frozen list of selected transactions, and per-row “Previewed · Not sent” results. Neither action calls a backend, queues jobs, checks live eligibility, or changes transaction status. Copy selected references uses the browser clipboard with error feedback. Selected CSV export remains available. Financial mutations are not exposed. Live callback/resync integration must validate authorization, eligibility, deduplication/rate limits and job outcomes on the backend.

The toolbar now has two rows: search/multi-search, saved-view picker and View controls, then quick/advanced filters and sorting. Reset is conditional on active search/filters. Multi-search uses a count and editable dialog instead of an expanding chip list. Sorting labels derive from the actual table sorting, including custom header sorts; saved views retain the complete sorting state. Reference and checkbox columns are pinned, column widths are tailored, and money headers align right. A single table scroll container supports the sticky header. Footer reports the visible result range and localizes pagination labels.

External/order ID is hidden by default and can be enabled through View. Saved views use a “Default view” label instead of a second “All” tab, with session-only storage explained below the controls. The matching-result count is in the pagination footer rather than above the toolbar.

Unit tests validate fixtures, simple search filters, advanced AND/OR/range filters, conjunctive quick filters and request cancellation. Browser tests exercise tabs, multi-search Apply/Cancel and deduplication, period Apply/Cancel, advanced datetime ranges, pagination movement, detail navigation/Escape, saved-view creation, density, selection, export, errors/retry, and mobile document overflow. Desktop, dark and mobile screenshots are saved under `test-results/transactions-*.png`. Copy feedback, every preset and every sorting/column-control combination have not received dedicated browser coverage. Some newly added locale keys intentionally inherit English; key parity is not translation completeness. This is not a comprehensive accessibility or pixel-parity audit.
