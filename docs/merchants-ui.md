# Merchant UI demo

`/merchants` and `/merchants/manage` render the same authenticated, merchant-view-permission-protected workspace. `/merchants/performance` remains a separate pending integration.

The workspace uses 32 explicitly synthetic fixtures. Create, edit, lifecycle changes and activity history live in a merchant-layout context, survive client-side navigation between merchant pages and reset on reload or leaving the merchant layout. No merchant API, credential issuance, notifications, document verification, bank account provisioning or financial mutation is called. UI copy currently uses English in all locales; existing locale routing and shell translations are unchanged.

Routes: `/merchants` (list), `/merchants/create`, `/merchants/[merchantId]` (detail), `/merchants/[merchantId]/edit`. Record identifiers are dynamic data, not feature dispatchers. Detail has a merchant header, lifecycle actions, and keyboard-operable Business profile, Settlement, Integration and Activity tabs. List and activity both use the shared `DataTable` component. Unknown or reload-cleared IDs display a not-found explanation with a return link.

The list and Payments / Transactions now share `WorkspaceToolbar`, `WorkspaceTabs`, `WorkspaceFrame`, `WorkspaceError`, multi-search and UTC period dialogs, the advanced filter evaluator, view options and table bulk/pagination components. Domain wrappers supply their own fields and sort options, rather than duplicating toolbar markup. Merchant code and checkbox columns are pinned by default; density defaults to Normal and is controlled through View options. Saved views capture search, filters, sorting, visibility, pinning, density and work-area tab in workspace memory. Quick status/tier/period filters always narrow advanced AND/OR results. Bulk status requests reject selections with any ineligible merchant and show feedback without changing records.

Fields follow the IAM merchant create/update/response DTOs, with simplified demo tenant names and a comma-separated IP whitelist string. Lifecycle eligibility follows IAM's merchant status transition map, including terminal rejected/terminated states. This client-side eligibility is a preview, not backend authorization. Actual mutation permissions, tenant scoping, KYC evidence checks, IP/CIDR validation and concurrency checks must be enforced during API integration.

Features: onboarding/active/suspended work areas, multi-term search, status/tier/tenant/environment filters, sortable separate columns, column visibility, density, pagination, row selection, CSV export with formula escaping, bulk lifecycle eligibility, confirmation with reason, three-section create/edit pages, domain-tabbed detail page and activity history. Preview-state control exercises empty/error states; refresh uses a delayed local query without discarding edits. No browser persistence stores merchant data.
